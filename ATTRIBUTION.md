## 1. Why this register exists (NASA Space Apps terms)

The 2026 NASA Space Apps legal page ( https://www.spaceappschallenge.org/legal , read 2026-11-10 ) says, in summary:

- Original content created for the challenge must be freely available or licensed as open source (OSI definition). If no OSI-compliant licence is chosen, NASA distributes it under Apache 2.0.
- Third-party materials must be freely and publicly available without restriction, or at least licensed as open source.
- Every source used must be cited, **even if it is open source or freely available**. Uncited resources can cost a team its nominations, awards or winner status.

**The team must read the official terms itself.** This summary is not a substitute.

**REVIEW — project licence:** the team has not yet chosen a licence for its original content. Decide and add a `LICENSE` file. See README, "Project licence".

## 4. Libraries, frameworks and runtime dependencies

**None.** The site uses no npm packages, CDN scripts, frameworks, build tools or bundled third-party code. There is no `package.json` or lockfile, and nothing is loaded from external hosts at runtime.

It uses **built-in browser standards** only. These are platform features, not dependencies:

| Feature | Used for |
|---|---|
| ES modules, hash routing (`location.hash`, `history.replaceState`) | App structure and navigation |
| `localStorage` | Saving expedition progress |
| `<dialog>` element | Dossier window |
| Canvas 2D, `ResizeObserver`, `IntersectionObserver` | Waveform, resize handling, "read to the end" detection |
| **Web Speech API (`speechSynthesis`)** | Reading Last Transmissions aloud. No audio files are shipped. The voices belong to the visitor's device or browser vendor. |

**Development tools used while building (not shipped):** Node.js v22.23.4 (syntax checks) and Python 3.12.3 (packaging and edits), in the AI development sandbox. Recorded for reproducibility.

> If any dependency is added later, add a row here with its **exact version**, source URL, licence and creator, and add its licence text to `THIRD_PARTY_LICENSES.md` in the same commit.

**Policy for adding any image later.** NASA's Images and Media Usage Guidelines ( https://www.nasa.gov/nasa-brand-center/images-and-media/ , read 2026-11-10 ) say NASA content is generally not subject to copyright in the US for non-commercial use. They also say the NASA Insignia, Logotype and Seal are not public domain, and that use must not imply NASA endorsement. Individual images can carry other credits or rights. So for every image:

1. Open the image's own NASA page and record the exact credit line (for example "NASA/JPL-Caltech").
2. Record the source URL, the image ID, and any rights note on that page.
3. If the page names a third-party owner (a university, a contractor, a museum), treat it as **third-party** and check that owner's terms.
4. Add a row to this table **before** the file is committed, and put the credit in the event's `photo.credit` field.
5. Do not use an image that contains a NASA logo or insignia in a way that suggests endorsement.
